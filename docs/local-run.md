# Запуск с ноутбуков и подготовка демо

Сервер не нужен. Для разработки у каждого участника свой бот из BotFather,
свой `.env` и собственная SQLite-база. Токены и базы через Git не передаём.
Демонстрационный бот работает на одном выбранном компьютере. Резервный
подхватывает **того же бота и копию его базы**, когда основной остановлен.

## Первичная установка

Нужен Python 3.11+. Скопируйте/клонируйте исходники на компьютер; `.venv`
между компьютерами не переносится.

Windows, PowerShell:

```powershell
.\scripts\setup.ps1 -Dev
```

Если Python не в PATH, укажите интерпретатор:

```powershell
.\scripts\setup.ps1 -Python 'C:\Python313\python.exe' -Dev
```

Если политика PowerShell запрещает запуск скриптов, можно выполнить только
этот скрипт в отдельном процессе:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup.ps1 -Dev
```

macOS/Linux:

```sh
sh scripts/setup.sh --dev
```

Скрипты создают окружение, устанавливают проект и копируют `.env.example` в
`.env`, если этого файла ещё нет. Существующий `.env` не перезаписывается.
Без `-Dev` / `--dev` устанавливаются только зависимости запуска.

## Что заполнить вручную

1. Создать бота через BotFather, вставить токен в `BOT_TOKEN` локального `.env`.
2. Для преподавателей задать `TEACHER_REGISTRATION_CODE` либо использовать
   ручное назначение через `ADMIN_IDS` и `/grant_teacher`.
3. Запустить бота, отправить ему `/id` (или «❓ Помощь» → «🆔 Мой Telegram ID»)
   и при необходимости добавить свой числовой ID в `ADMIN_IDS=[123456789]`.
   После изменения `.env` перезапустить бота.
4. Участники демо также узнают свой ID; эти значения нужны для демобазы.

Один человек с одним Telegram-аккаунтом может быть преподавателем или студентом.
Для живой демонстрации двух ролей нужны разные аккаунты — например ваш и участника команды.

## Проверка и запуск

В Windows используйте `.\.venv\Scripts\python.exe`, в macOS/Linux —
`.venv/bin/python`. Далее в примерах указан Windows-путь; команды одинаковы.

```powershell
.\.venv\Scripts\python.exe -m labdefender.tools doctor
.\.venv\Scripts\python.exe -m labdefender.tools doctor --telegram
.\scripts\run.ps1
```

На macOS/Linux запуск — `sh scripts/run.sh`.

`doctor` проверяет настройки, версию SQLite, целостность, связи и необходимые
столбцы существующей базы. Если базы ещё нет, сообщает, что она создастся при
первом запуске. Секретные значения не выводятся. При чтении SQLite может
выполнить стандартное восстановление журнала после аварийного завершения.
`--telegram` дополнительно вызывает только `getMe` и `getWebhookInfo`:
проверяет доступ к боту и отсутствие webhook, сообщения не отправляет.

Скрипт запуска сначала выполняет локальный `doctor`, затем включает polling.
Остановка — `Ctrl+C`; перед переносом запуска дождитесь завершения процесса.
На основном ноутбуке во время демо оставьте приложение запущенным и отключите
автоматический сон на время выступления. Боту требуется интернет.

Повторный запуск с тем же ботом или той же базой блокируется в пределах
локального пользователя компьютера, включая другую папку проекта.
Между разными компьютерами блокировки нет: один токен использует только один
активный polling-процесс. Если Telegram сообщает `Conflict`, проверьте другие
компьютеры и терминалы, остановите лишний запуск. Резерв не запускается одновременно
с основным. Базу активного бота держите на локальном диске.

## Mini App через временный туннель

Mini App открывается по публичному HTTPS-адресу. Ноутбук такого адреса не имеет,
поэтому для разработки используется временный туннель Cloudflare: `cloudflared`
сам подключается к Cloudflare и выдаёт адрес `https://….trycloudflare.com`, роутер
и порты настраивать не нужно. Регистрация в Cloudflare не требуется.

Установка один раз:

```sh
brew install cloudflared                       # macOS
winget install --id Cloudflare.cloudflared     # Windows, затем новый терминал
```

Запуск — обычный скрипт с флагом:

```powershell
.\scripts\run.ps1 -Tunnel
```

На macOS/Linux — `sh scripts/run.sh --tunnel`. Скрипт выполняет `doctor`, запускает
`cloudflared`, ждёт адрес (до 30 секунд), печатает `Mini App: https://…/app/`, поднимает
веб-сервер на `127.0.0.1:8080` и бота, ставит кнопку «Приложение». `Ctrl+C`
останавливает всё вместе с туннелем. Без флага всё работает как раньше.

**Туннель в отдельном окне.** Чтобы перезапуск бота не менял адрес, запустите
туннель отдельно и оставьте окно открытым:

```sh
sh scripts/tunnel.sh
```

В Windows — `.\scripts\tunnel.ps1`. Окно печатает `Mini App: https://…/app/` и держит
`cloudflared`. Бот в другом окне запускайте как обычно, с `--tunnel` (`-Tunnel`): он
находит этот туннель и пишет «Адрес взят у туннеля в отдельном окне». Теперь `Ctrl+C`
в окне бота туннель не трогает, а следующий запуск бота получает тот же адрес.
`Ctrl+C` в окне туннеля останавливает его — адрес перестаёт работать, следующий
запуск бота поднимет новый. Если `cloudflared` остановился сам, окно туннеля
сообщит об этом и закроется. Второй такой туннель к тому же `WEB_PORT` не
запускается: окно подскажет адрес уже работающего. Пока бот остановлен, адрес
отвечает страницей ошибки Cloudflare, а после запуска бота снова работает.

Ограничения временного туннеля:

- адрес новый при каждом запуске туннеля, кнопки со старым адресом в прошлых сообщениях
  не работают; кнопку у поля ввода Telegram обновляет с задержкой до пары минут, и до
  этого она открывает прежний адрес — страница Cloudflare «Error 1033». Подождите,
  закройте и снова откройте чат (на телефоне иногда — перезапустите Telegram) или
  отправьте `/start` — его кнопка всегда с текущим адресом;
- Cloudflare не гарантирует работу таких туннелей; порядок демо без своего домена —
  «Демо на временном адресе», надёжнее — «Постоянный адрес для демо»;
- если есть `~/.cloudflared/config.yml`, временный туннель не запускается;
- сеть университета или офиса может блокировать туннель — проверьте заранее,
  запасной вариант — раздача интернета с телефона;
- порт занят — задайте другой `WEB_PORT` в `.env`;
- трафик Mini App проходит через Cloudflare.

Ручная проверка Mini App:

- кнопка «Приложение» у поля ввода видна и открывает адрес из терминала (иначе
  подождите пару минут, закройте и откройте чат); `/app` сразу даёт кнопку с текущим
  адресом;
- приложение открывается на iPhone, Android и в Telegram Desktop, показывает своё имя
  и роль; цвета следуют светлой и тёмной теме Telegram;
- преподаватель: «🗓 Слоты и очередь» → группа; «Новый слот» внизу (кнопка
  Telegram) → дата → время → длительность → места → «Создать слот»; «Назад» в шапке
  Telegram возвращает на шаг; допущенный студент без записи получает уведомление;
  в очереди слота работают «Закрыть», «Открыть» и «Отменить» (с подтверждением);
- студент: «📚 Задания» → карточка с условием и статусом; ответ текстом или ссылкой
  уходит на проверку, преподаватель получает уведомление; «Отправить файл PDF/ZIP
  через чат» — бот пишет в чат, файл присылается туда и подтверждается; «Мои попытки»
  и комментарий видны; после допуска «🗓 Защита и очередь» → группа — допущенные работы,
  запись работы в слот, смена слота, «В конец очереди»; две допущенные работы записываются
  в один слот на разные места, очередь слота у преподавателя показывает задание и попытку;
- отчёты: преподаватель — «📊 Отчёты» → группа → таблица (ячейка → подробности, имя →
  отчёт студента), «Прислать таблицу в чат» → CSV открывается в Excel; студент — «📊 Мой
  отчёт»; в чате `/report` присылает тот же файл;
- преподаватель: «📥 На проверку» — «Допустить» и «Вернуть с комментарием», для файла
  «Прислать файл в чат»; «👥 Группы» → «Новая группа» → «Поделиться» ссылкой;
  «📝 Задания» → «Новое задание» → студенты получают уведомление;
- «📱 Открыть в приложении» под уведомлением открывает тот же объект (попытку,
  задание, защиту, группу, очередь слота); после `/start` приходит кнопка приложения;
- «👤 Профиль»: имя меняется и сохраняется после нового открытия приложения и сообщений
  боту, «Вернуть имя из Telegram» возвращает прежнее; то же в чате через «✏️ Моё имя»;
  преподаватель в карточке группы открывает «👥 Посмотреть студентов» и видит новое имя
  и username; Telegram ID копируется; студент вводит код преподавателя — приложение
  показывает разделы преподавателя, в чат приходит меню преподавателя; администратор
  выдаёт роль по ID; преподаватель в «🔔 Уведомления» выключает и включает категории,
  и это же видно в «🔔 Уведомления» чата;
- адрес из терминала в обычном браузере показывает «Откройте приложение из Telegram»;
- после остановки бота приложение показывает «Сервер недоступен»; после нового
  запуска с `--tunnel` кнопка ведёт на новый адрес.

## Демо на временном адресе

Без своего домена демо проводится на временном туннеле в отдельном окне:

1. За 10–15 минут до начала, на основном ноутбуке с отключённым сном: окно 1 —
   `sh scripts/tunnel.sh` (`.\scripts\tunnel.ps1`), окно 2 — `sh scripts/run.sh --tunnel`
   (`.\scripts\run.ps1 -Tunnel`). В окне бота дождитесь «Адрес взят у туннеля
   в отдельном окне» и «Mini App открывается по публичному адресу…».
2. Участники отправляют боту `/start`: под ним приходит кнопка приложения с текущим
   адресом. Кнопка «Приложение» у поля ввода обновится через пару минут.
3. Окно туннеля не закрывайте до конца демо. Бота можно перезапускать (`Ctrl+C`
   в окне 2 и тот же запуск): адрес и кнопки в уведомлениях сохраняются.
4. Если адрес всё же сменился (перезапуск окна туннеля, ноутбука, долгий обрыв сети,
   переход на резерв), участники снова отправляют `/start` или `/app`. Кнопки
   «📱 Открыть в приложении» в уведомлениях до смены адреса больше не работают;
   кнопки чата под теми же уведомлениями работают.
5. Резервный ноутбук поднимает свой туннель тем же способом, адрес у него будет
   новым — поэтому до демо проверьте на нём оба окна, затем остановите их.

## Постоянный адрес для демо

Временный адрес меняется при каждом запуске, а кнопки в уже отправленных сообщениях
хранят старый. Для демо нужен постоянный адрес: туннель Cloudflare на поддомене
вашего домена, например `https://lab.example.org`. Нужны аккаунт Cloudflare
(бесплатный план) и домен, DNS которого обслуживает Cloudflare; это решение
команды — без своего домена остаётся временный адрес или собственный сервер с HTTPS.

Один раз, в панели Cloudflare:

1. Zero Trust → Networks → Tunnels → создать туннель типа Cloudflared, имя любое,
   например `labdefender`.
2. На шаге установки панель показывает команду с длинным токеном после `--token`.
   Скопируйте **только токен**. Саму команду не выполняйте и не ставьте `cloudflared`
   службой (`service install`): туннель-служба работает и без бота, а на резервном
   ноутбуке — одновременно с основным.
3. Добавьте адрес туннеля (Public Hostname; в новых версиях панели — Published
   application routes): поддомен `lab`, ваш домен, тип сервиса `HTTP`, URL
   `127.0.0.1:8080` — именно `127.0.0.1` и порт из `WEB_PORT`; с `localhost`
   `cloudflared` может пойти по IPv6, а веб-сервер слушает только IPv4.

На основном и резервном ноутбуке в `.env`:

```dotenv
WEBAPP_URL=https://lab.example.org
TUNNEL_TOKEN=<токен>
```

Токен — секрет, как `BOT_TOKEN`: с ним кто угодно может обслуживать ваш адрес.
Не добавляйте его в Git и не пересылайте в общих чатах; если утёк — в панели
обновите токен туннеля (refresh token) и замените его в `.env` обоих ноутбуков.

Проверка и запуск:

```sh
.venv/bin/python -m labdefender.tools doctor
sh scripts/run.sh --tunnel
```

`doctor` пишет «OK: постоянный туннель Cloudflare…» и куда должен вести адрес. Запуск
поднимает `cloudflared` с этим токеном (через переменную окружения), ждёт подключения
до 30 секунд, печатает `Mini App: https://lab.example.org/app/ (постоянный адрес)`
и запускает бота. Затем бот сам открывает адрес через интернет и пишет в консоль:

- «Mini App открывается по публичному адресу…» — всё готово;
- «…не открылась… ответ HTTP 502» и похожее — в Cloudflare адрес ведёт не на
  `127.0.0.1:<WEB_PORT>` или туннель не тот;
- «…ошибка соединения…» — DNS ещё не обновился, нет интернета или `WEBAPP_URL`
  не совпадает с адресом туннеля;
- «По адресу Mini App отвечает другой запуск LabDefender» — тем же туннелем
  пользуется второй компьютер; остановите лишний запуск.

Если `cloudflared` не подключился (неверный токен, нет сети), запуск останавливается
с подсказкой и сообщением самого `cloudflared`, например «Provided Tunnel token is not
valid.». С постоянным адресом кнопка «Приложение» после первого запуска больше не
меняется, поэтому задержки и «Error 1033» после перезапусков нет.

**Резервный ноутбук.** Тот же `WEBAPP_URL` и `TUNNEL_TOKEN`, запуск так же с
`--tunnel`. Одновременно оба запуска не держите: кроме конфликта polling, Cloudflare
делит запросы приложения между подключёнными ноутбуками, и студенты попадут в разные
базы. Переход — по разделу «Восстановление и переход на резерв»: остановить основной,
дождаться выхода, восстановить копию базы, запустить резерв; адрес и кнопки в старых
сообщениях остаются рабочими.

## Проверка без токена и сети

```powershell
.\.venv\Scripts\python.exe -m labdefender.tools smoke
```

Команда создаёт временную базу, проходит роли, группу, задания, сдачу, возврат,
допуск и очередь, проверяет backup/restore, затем удаляет временные данные.
Основной `.env` и учебная база не меняются. Telegram-интерфейс дополнительно
проверяется тестами:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

## Демобаза с настоящими участниками

Сначала получите ID через `/id`. В примере замените числа на реальные:

```powershell
.\.venv\Scripts\python.exe -m labdefender.tools seed-demo --teacher-id 123456789 --student-id 234567890 --student-id 345678901
```

Последний `--student-id` можно убрать или повторить для других участников.
Создаётся **новый** `data/demo.sqlite3`: группа, три задания с разными форматами
сдачи, слоты защиты группы и общая очередь, попытка на проверке и возвращённая
попытка первого студента. Два слота на завтра и один на послезавтра; в первом слоте —
ЛР 1 всех студентов и ЛР 2 последнего студента (работы разных заданий в одной очереди). Преподаватель и студенты уже имеют роли и участие.
Никаких сообщений в Telegram команда не отправляет. Уведомления начнут приходить
участникам только при действиях в запущенном боте — предупредите их перед репетицией.

Если файл существует, команда остановится без перезаписи. Для другой подготовки
задайте `--output data/demo-next.sqlite3`. Учебная база не очищается.
После создания остановите бота, выберите файл в `.env`:

```dotenv
DATABASE_URL=sqlite+aiosqlite:///./data/demo.sqlite3
```

Запустите `doctor`, затем бота. При первом обращении имена аккаунтов обновятся
из Telegram. Попросите участников отправить `/start`: меню кнопок своей роли приходит
с ним (а также с `/cancel` и в ответ на непонятное сообщение), в чатах, открытых
до обновления бота, его ещё нет. Для показа настоящего PDF/ZIP участник отправляет файл во время
репетиции: в seed-данных используются текст и ссылка, фиктивных `file_id` нет.

## Миграция старой демобазы

Если база была создана до появления форматов заданий и слотов или до общей очереди
группы (слоты были у каждого задания свои), `doctor` и запуск бота остановятся с
подсказкой. Остановите бота и выполните:

```powershell
.\.venv\Scripts\python.exe -m labdefender.tools migrate --database data/demo.sqlite3
```

В Linux/macOS — `.venv/bin/python -m labdefender.tools migrate --database data/demo.sqlite3`.
Слоты заданий станут слотами их групп, записи очереди получат студента и задание,
порядок и места сохранятся. Самые старые «дни защиты» станут слотами с временем
`09:00–18:00`; формат существующих
заданий будет `online`. Перед изменением создаётся копия в `backups/` рядом с базой.
Повторный запуск безопасен. После миграции выполните `doctor` и запустите бота.

## Резервное копирование

```powershell
.\.venv\Scripts\python.exe -m labdefender.tools backup
```

По умолчанию источник берётся из `DATABASE_URL`, копия записывается новым файлом
в `backups/` с UTC-временем в имени. Токен для этой операции не нужен.
Можно явно задать исходный файл и новое имя:

```powershell
.\.venv\Scripts\python.exe -m labdefender.tools backup --database data/demo.sqlite3 --output backups/before-demo.sqlite3
```

Копия делается SQLite Backup API, поэтому включает подтверждённые данные из WAL
и может создаваться при работающем боте. Это не копирование одного файла
проводником во время записи. После завершения проверяются целостность и схема.
База, созданная до появления таблиц `teacher_registration_attempts`,
`notification_settings` или `user_profiles`, тоже копируется: эти таблицы бот создаст
при следующем запуске.
Существующий файл назначения не перезаписывается. `.env` в копию не входит.

## Восстановление и переход на резерв

1. Остановить основной запуск. Установить ту же версию проекта на резервном
   компьютере через setup, отдельно заполнить `.env` токеном **того же бота**.
2. Передать последнюю завершённую SQLite-копию на резервный компьютер.
3. Восстановить её в новый файл:

```powershell
.\.venv\Scripts\python.exe -m labdefender.tools restore backups/before-demo.sqlite3 --output data/restored.sqlite3
```

4. Выбрать этот файл в `.env`:

```dotenv
DATABASE_URL=sqlite+aiosqlite:///./data/restored.sqlite3
```

5. Выполнить `doctor --telegram`, запустить бота, проверить `/start` и кнопки меню
   («📚 Задания» / «📥 На проверку», «🗓 Защита и очередь») с аккаунтов преподавателя
   и студента. Если используется Mini App, на резервном компьютере запускайте
   с `--tunnel`. С временным туннелем адрес будет новым: кнопку у поля ввода бот
   обновит сам, а кнопки в старых сообщениях работать перестанут. С постоянным
   адресом (`TUNNEL_TOKEN` и `WEBAPP_URL` те же, что на основном) адрес не меняется;
   дождитесь в консоли «Mini App открывается по публичному адресу…».

Восстановление не заменяет существующую базу: если новый путь уже занят, команда
откажется. Можно выбрать другое имя. Исходная база и копия сохраняются.
У того же бота остаются ссылки, Telegram ID и доступ к сохранённым `file_id`;
для другого бота старые файловые идентификаторы использовать нельзя.

## Репетиция перед защитой

- Каждый участник отправляет `/start` и видит меню своей роли; преподаватель
  кнопками меню открывает демогруппу, задания на проверку и очередь.
- Преподаватель создаёт слот кнопками: дата в календаре, время, длительность, места;
  ещё один — кнопкой «Как в прошлый раз» на другую дату. Если демо идёт с Mini App —
  то же в приложении («🗓 Слоты и очередь»).
- Уведомления доходят: преподавателю — о новом решении и записи на слот, студенту —
  о возврате, допуске и новом слоте. «🔕 Не присылать такие» выключает категорию,
  «🔔 Уведомления» включает её обратно.
- Студент открывает возвращённую работу, читает комментарий и пересдаёт PDF/ZIP.
- Преподаватель открывает файл и допускает новую попытку.
- Студент выбирает слот и работу, показывает позицию; преподаватель видит тот же порядок
  с заданием и попыткой. Вторая работа того же студента встаёт в тот же слот отдельно.
- Преподаватель присылает себе отчёт по группе (`/report` или приложение), открывает его
  в Excel; студент получает свой отчёт.
- Перенос в конец меняет порядок, смена на заполненный слот сохраняет прежнее место.
- Перезапуск сохраняет роли, решения и очередь; незавершённый ввод начинается заново.
- Сделана копия базы; резервный запуск подготовлен и остановлен до необходимости.

Если демо идёт с Mini App (постоянный адрес или временный туннель в отдельном окне,
см. «Демо на временном адресе»):

- В консоли после запуска — «Mini App открывается по публичному адресу…».
- Приложение открывается кнопкой «Приложение» на iPhone, Android и в Telegram Desktop
  у преподавателя и студента; тема (светлая/тёмная) следует Telegram; «Назад» и
  главная кнопка внизу — родные кнопки Telegram; подтверждения — окна Telegram.
- Основные сценарии из «Ручная проверка Mini App» проходят на телефоне: слот, ответ
  студента, проверка, запись на защиту, «Поделиться» приглашением.
- «📱 Открыть в приложении» под уведомлением открывает нужный экран.
- Перезапуск бота (`Ctrl+C`, снова `--tunnel`): пока бот остановлен, уже открытое
  приложение на действия отвечает «Сервер недоступен», а новое открытие показывает
  страницу ошибки Cloudflare. После запуска «Повторить» работает, кнопки в старых
  уведомлениях открывают приложение — с постоянным адресом и с временным в отдельном
  окне; адрес в консоли бота тот же, что до перезапуска.
- Резерв: основной остановлен, резервный запущен с копией базы (с постоянным адресом —
  с тем же токеном), в консоли резервного — «Mini App открывается…», приложение
  открывается и показывает данные из копии; с временным туннелем — по новому адресу
  после `/start`. После проверки резерв остановлен.

Локальные проверки и тесты не заменяют эту репетицию с настоящим Telegram.
